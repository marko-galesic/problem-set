Progression: This is the harder, continuous-interval version of House Robber. Give it directly to senior candidates. For junior candidates, start with House Robber; offer this only if they finish with time remaining. If a candidate is stuck on the interval structure, step down to House Robber and return here if time permits.

Target insight

Sort ads by finish time. For each ad i, find the latest earlier ad p(i) whose finish time is at most start[i]. Exact endpoint contact is allowed. Use binary search for p(i), then compute:

dp[i] = max(dp[i - 1], payout[i] + dp[p(i)])

With a one-based DP array, dp[0] = 0 and the compatible-prefix count can be used directly as the second DP index. Expected complexity is O(n log n) time and O(n) space.

Photographed example

[[1,4,3], [3,7,7], [6,10,8], [9,10,5]]

The best schedule takes [3,7,7] and [9,10,5] for a total of 12. Choosing the individually highest-paying ad, [6,10,8], is a greedy trap. Ordering the intervals before applying the recurrence is essential.

Expected signals and scoring

  • Recognizes a left-to-right cumulative value function: +2.
  • Solves the concrete example step by step and explains the choices: +2.
  • Defines an appropriate cumulative DP value: +1.
  • In the inductive step, identifies the latest non-overlapping predecessor: +2.
  • Uses binary search to find that predecessor: +1.
  • States the correct include-or-skip recurrence: +2.
  • Sorts by end time: +1.

Attempts

A correct solution on the first attempt earns +4. Subtract 1 for each additional attempt (the photographed rubric begins with three allowed attempts). Track conceptual attempts, not harmless syntax corrections.

Pitfalls and prompts

  • Highest payout first: ask whether one expensive interval can block two compatible intervals worth more together.
  • Earliest start or shortest duration first: ask what local property proves global optimality.
  • Quadratic predecessor scan: accept the DP insight, then ask how sorted finish times change the predecessor lookup.
  • Endpoint bug: reinforce that end == start is compatible, so the search comparison is <=.
  • Unsorted assumption: use the chain [[5,7,5],[0,2,4],[2,5,6]], whose answer is 15.
